# Порядок загрузки mise.toml при активации окружения

> Ресерч делался на основе версии 2025.11.3

Когда у вас настроена интеграция mise с shell (`eval "$(mise activate bash)"`) и вы переходите в директорию 
с `mise.toml`, mise автоматически загружает конфигурацию и настраивает окружение. Важно понимать **в каком порядке** 
это происходит, чтобы правильно выстраивать зависимости между секциями.

---

**Порядок загрузки**

```
┌─────────────────────────────────────────────────────────────────────────┐
│              Порядок загрузки при cd в папку                            │
├─────────────────────────────────────────────────────────────────────────┤
│ 1. [vars]            - переменные для шаблонов                          │
│ 2. [alias]/[plugins] - опционально                                      │
│ 3. [env] БЕЗ tools   - базовые переменные окружения (первый проход)     │
│ 4. [tools]           - установка/проверка инструментов                  │
│ 5. [env] С tools     - переменные после установки tools (второй проход) │
│ 6. Применение        - export в shell                                   │
└─────────────────────────────────────────────────────────────────────────┘
```

**Ключевые правила**

- **`[[env]]` блоки** выполняются **в порядке написания** в файле, по этому, если важен порядок, используйте их вместо одного блока `[env]`
    - но с учетом **двух проходов**: сначала директивы БЕЗ `tools=true`, потом С `tools=true`
    - несколько директив с `tools=true` будут загружаться в порядке объявления
- **vars** НЕ может использовать env или tools
- **env** может использовать vars ВСЕГДА
- **env** может использовать tools ТОЛЬКО когда директива имеет параметр `tools=true`
- **_.python.venv** ВСЕГДА имеет `tools=true` (нельзя изменить)
- **Порядок `_.*` директив** внутри `[env]` жестко закодирован: `_.path` → `_.file` → `_.source` → другие → `_.python.venv`

**Доступность данных в templates**

| Секция           | vars | env (pass 1) | tools | env (pass 2) |
|------------------|------|--------------|-------|--------------|
| `[vars]`         | ✅   | ❌           | ❌    | ❌           |
| `[env]` pass 1   | ✅   | ✅           | ❌    | ❌           |
| `[env]` pass 2   | ✅   | ✅           | ✅    | ✅           |

**Что доступно в шаблонах:**
- `{{config_root}}` - путь к директории с mise.toml
- `{{cwd}}` - текущая рабочая директория
- `{{vars.NAME}}` - переменные из [vars]
- `{{env.NAME}}` - переменные окружения

### Примеры решения проблем

**Использование VIRTUAL_ENV без установки tools=true**

```toml
[[env]]
_.python.venv = { path = ".venv", create = true }
MY_PATH = "{{env.VIRTUAL_ENV}}/data"  # ❌ VIRTUAL_ENV еще нет!
```

Решение: добавьте `tools = true`

```toml
[[env]]
MY_PATH = { value = "{{env.VIRTUAL_ENV}}/data", tools = true }  # ✅
```

Переменная `VIRTUAL_ENV` создается после того как инициализированы tools и после `_.python.venv`, а обычные 
переменные окружения без `tools = true` загружаются на первом проходе.

**Использование env в vars**

```toml
[vars]
OTHER_VAR = "{{env.MY_VAR}}"  # ❌ env не доступны в vars!
```

Решение: используйте vars или переместите в [env]

```toml
[vars]
OTHER_VAR = "{{vars.MY_VAR}}"  # ✅
```

**Скрипт выполняется до установки tools**

```toml
[[env]]
_.source = "setup.sh"  # ❌ Скрипту нужен Python, но его еще нет!
```

Решение: добавьте `tools = true`

```toml
[[env]]
_.source = { path = "setup.sh", tools = true }  # ✅
```

**Ожидание порядка `_.*` директив внутри `[env]`**

Порядок выполнения директив жестко закодирован: `_.file` → `_.source` → `_.python.venv`

```toml
[env]
_.python.venv = { path = ".venv", create = true }
_.source = "script.sh"
_.file = ".env"
```

Решение: объявите отдельные [[env]] блоки и расположите их в нужном порядке (но не забывайте, что параметр `tools` 
оказывает все равно влияение на порядок загрузки и что есть 2 прохода)

```toml
[[env]]
_.file = ".env"

[[env]]
_.source = "script.sh"

[[env]]
_.python.venv = { path = ".venv", create = true }
```
